## 五、缺陷发现与修复详情

共处理 **8 类缺陷**（含 4 个可导致程序崩溃的 Bug 和 4 类体验/鲁棒性问题）。下表按严重程度排列。

---

### 缺陷 #1：未选目标任务时推理线程崩溃 【严重 · 已修复】

| 项目 | 内容 |
|------|------|
| **影响模块** | `YYnet-main/app.py` → `run_pipeline_sync` / `run_index_pipeline_sync` |
| **现象** | 侧栏显示「未发现可用任务」时，用户仍可点击「运行模型推理」，后台线程抛出 `TypeError` 并闪退 |
| **报错信息** | `TypeError: join() argument must be str, bytes, or os.PathLike object, not 'NoneType'` |
| **根因** | `selected_task=None` 时 `actual_task` 为 `None`，`os.path.join(root_dir, actual_task)` 无法拼接 |
| **修复方式** | 在 `join` 前增加前置校验：若 `actual_task` 或 `root_dir` 为空，推送中文错误提示并安全返回 |
| **验证** | E2E 第 13 项「app.py 空 task 防御」通过 |

```python
# 修复前
input_dir = os.path.join(root_dir, actual_task)

# 修复后
if not actual_task or not root_dir:
    push_status("error", "未选择有效目标任务，或原始影像目录未配置。")
    return False
input_dir = os.path.join(root_dir, actual_task)
```

---

### 缺陷 #2：post_engine 误将输出 SHP 当作岸线裁剪栅格读取 【严重 · 已修复】

| 项目 | 内容 |
|------|------|
| **影响模块** | `YYnet-main/post_engine.py` → `generate_double_constraint_complete` |
| **现象** | 时空合成流程在阶段 3 读取岸线裁剪掩膜时，将尚未生成的输出 SHP 当作栅格读取，整个合成返回 `False` |
| **报错信息** | `rasterio.errors.RasterioIOError: ...Final_p0.05_c2.shp: TIFFReadDirectory:Failed to read directory` |
| **根因** | 当 `shp_path` 与 `output_path` 相同时，未排除自身；且读取失败时未降级处理 |
| **修复方式** | ① 排除 `shp_path == final_shp_path` 的情况；② 读取失败时 `try-except` 跳过裁剪，不中断主流程 |
| **验证** | E2E 第 11 项「post_engine 时空合成」通过 |

---

### 缺陷 #3：combine.py 污染模块导入路径，导致加载旧版 post_engine 【严重 · 已修复】

| 项目 | 内容 |
|------|------|
| **影响模块** | `jb/combine.py`（间接影响所有依赖 `post_engine` 的脚本） |
| **现象** | E2E 全量运行时，`combine` 测试通过后 `post_engine` 突然失败；单独运行 `post_engine` 却成功 |
| **根因** | `sys.path.insert(0, YYnet)` 将旧版 `YYnet/post_engine.py` 插到 `YYnet-main/post_engine.py` 之前，导致导入污染 |
| **修复方式** | 调整 `sys.path` 插入顺序：**优先 `YYnet-main`，再 `YYnet`** |
| **验证** | E2E 13/13 全通过；UX 回归 13/13 通过 |

---

### 缺陷 #4：E1 未对自相交脏多边形做拓扑修复 【严重 · 已修复】

| 项目 | 内容 |
|------|------|
| **影响模块** | `jb/E1.py` → `normalize_vector` / `load_dataset` |
| **现象** | 导入自相交 bowtie 多边形后，`unary_union` / `rasterize` 抛出 `TopologicalError` 或产生空几何 |
| **根因** | 数据清洗流水线仅过滤 `is_empty`，未调用 `make_valid` / `buffer(0)` |
| **修复方式** | 在 `normalize_vector` 中统一调用 `cstf_ux.repair_geometries()`，自动修复无效几何并打印中文日志 |
| **验证** | E2E 第 8 项 + UX 第 4 项通过 |

---

### 缺陷 #5：M5 两期要素无重叠时仍执行差集运算 【中等 · 已修复】

| 项目 | 内容 |
|------|------|
| **影响模块** | `jb/M5.py`、`YYnet-main/m5_engine.py` |
| **现象** | 基线（杭州湾）与当期（125°E 远离区域）完全不相交时，旧版仍做 overlay，可能产生误导性变化指标 |
| **根因** | 缺少 union 级空间交集前置判断 |
| **修复方式** | 增加 `geometries_have_overlap()` 检测；无重叠时输出提示「变化率计为 0.00%」，生成空白变化图层并安全退出 |
| **验证** | UX 第 1、5 项 + E2E 第 5 项通过 |

---

### 缺陷 #6：E1 无重叠时仍执行昂贵的分块栅格化 【中等 · 已修复】

| 项目 | 内容 |
|------|------|
| **影响模块** | `jb/E1.py` |
| **现象** | 目标 SHP 与参考层无空间交集时，仍进行全国范围分块栅格化（耗时数小时），IoU 含义不明 |
| **根因** | 缺少矢量级 `_gdf_spatial_overlap` 前置路由 |
| **修复方式** | 无重叠时直接返回 `jaccard_iou=0.0, skipped_raster_compare=True`，跳过后续栅格化 |
| **验证** | UX 第 3 项通过 |

---

### 缺陷 #7：路径输入容错不足 【中等 · 已修复】

| 项目 | 内容 |
|------|------|
| **影响模块** | `jb/M5.py`、`m5_engine.py`、`jb/E1.py`、`app.py` |
| **现象** | 路径末尾多 `\`、混用 `/`、带引号时直接 `FileNotFoundError` |
| **根因** | 未对用户输入做 `normpath` / `abspath` 清洗 |
| **修复方式** | 新建共享工具库 `cstf_ux.py`，提供 `normalize_path()` 函数，各模块统一调用 |
| **验证** | UX 第 2 项通过 |

---

### 缺陷 #8：分母为零时存在潜在除零风险 【中等 · 已修复】

| 项目 | 内容 |
|------|------|
| **影响模块** | `jb/M5.py`（面积变化率、紧凑度计算） |
| **现象** | 基线面积为 0 或紧凑度分母为 0 时，可能触发 `ZeroDivisionError` |
| **根因** | 直接除法，未做分母安全校验 |
| **修复方式** | 在 `cstf_ux.py` 中实现 `safe_div()` / `safe_pct_change()`，M5 全链路替换 |
| **验证** | M5 全链路隐式验证 + 边界矩阵通过 |
